# ICE-01 项目内核与可靠保存

> 状态：planned_not_dispatched
>
> 目标里程碑：E2 项目内核
>
> 上游依赖：E1 能力真实化完成；当前 P0-2 项目存储获得显式派工与文件锁。

## 目标

让用户选择的项目目录成为唯一事实来源：项目可以创建、打开、原子保存、重开、迁移和从受控失败恢复，不依赖浏览器多 key 状态或绝对路径。

## 范围

- `ProjectDocument` 的版本、revision、迁移与恢复语义。
- 项目目录创建、打开、保存队列、临时文件、原子替换和恢复文件。
- 中文/空格/长路径、损坏项目、旧版/未来版、强制结束 fixture。
- 类型化 IPC/受控接口与稳定错误码。

## 非目标

- 资产导入、媒体渲染、时间线新功能、Android/Web 构建、AI 与协作。
- 修改既有 UI 以营造保存成功假象。
- 任何项目脚本或任意文件操作能力。

## 计划文件范围

派工时以当前 `docs/orchestration/file-locks.md` 为准；预期涉及 `src/project/**`、`shared/contracts/project*`、受控 Electron project IPC 与对应测试。不得顺带重构时间线、播放器、资产管理或发布系统。

## 验收

1. 新建、连续编辑、保存、关闭和重开后项目 revision 与内容一致。
2. 强制结束后恢复最后一次成功 revision 或给出稳定恢复错误，不覆盖原文件。
3. 移动整个项目目录后可重新打开；绝对路径和项目外引用不写入项目文档。
4. 损坏、旧版、未来版和写入失败都有稳定错误码、原项目保护与 fixture。
5. 自动化测试、安装版/受控环境 smoke 与独立验收分别落档。

## 停止条件

出现静默覆盖、数据丢失、目录逃逸、未审查 IPC 或无法证明原子保存时，停止并保持 E2 blocked。
