# 0.9.0 发布候选版

> - 计划版本：`0.9.0-rc.1`，必要时递增 rc 序号
> - 发布通道：Release Candidate
> - 当前状态：planned
> - 内部映射：M6-B
> - 主要结果：形成一个可签名验证、可小范围分发、可直接晋升或回退的候选包

## 用户结果

候选测试用户获得的安装包、文档和 1.0 预期一致。候选期只处理发布阻断缺陷，不再改变功能范围或项目格式。

## 本版本范围

- 使用正式发布主体完成 Windows 代码签名和可信时间戳。
- 在 Windows 10、Windows 11 和常见 DPI 组合完成干净机测试。
- 验证从 `0.5.x`、`0.6.x`、`0.7.x` 项目打开和迁移到候选版。
- 验证覆盖安装、手工升级、卸载和重新安装不删除用户项目。
- 生成候选版 release notes、known issues、用户指南和故障恢复说明。
- 记录 installer、unpacked、二进制、FFmpeg 和 source commit hash。
- 建立候选观察期、问题分级、停止发布和回退流程。
- 对候选用户收集的诊断信息执行明确同意与脱敏规则。

## 变更规则

- rc 期间禁止新增功能、schema 字段和新的外部依赖。
- 仅修复 P0、P1 和经批准的高影响 P2。
- 任何行为变更都必须重新执行完整候选矩阵并递增 rc 序号。
- 不能通过文档规避真实产品缺陷。

## 候选观察门槛

- 每个 RC 至少观察 7 个完整自然日；修复 P0/P1 或用户旅程行为缺陷后发布新 RC 并重新计算观察期。
- 累计不少于 10 名目标用户在冻结支持矩阵内参与有效验证，其中至少 8 人仅依赖候选安装包和拟公开文档完成 1.0 核心用户旅程。
- 有效验证必须记录安装来源、系统环境、完成步骤、失败点与恢复结果；工程人员代操作的场次不计入完成率。
- 数据丢失、安全越界、假成功、安装阻断和无法回退不参与完成率折算，出现任一项即停止候选晋级。
- 用户研究样本、诊断同意和脱敏记录必须可追溯，但发布证据不得包含用户原始项目内容。

## 硬验收

- 签名链和时间戳在离线检查中有效，安装器显示正式发布主体。
- 下载后的安装包 hash 与发布清单一致。
- 干净 Windows 测试机完成安装、创建项目、导入、编辑、重启恢复、项目导出、MP4 导出和卸载。
- 已支持旧版本项目均能迁移；失败时保留原文件和恢复说明。
- 候选观察期内 P0 为 0，P1 为 0。
- 候选观察达到 7 天、10 名有效用户和至少 80% 独立完成率。
- 不存在未批准的安全、许可、隐私或 SmartScreen 阻断。
- 发布、停止发布和回退步骤均经过桌面演练。

## 失败判定

- 候选期继续加入功能或改项目模型。
- 未签名包被当作正式候选。
- 覆盖安装或卸载会删除用户项目。
- 已知 P0/P1 通过“正式版再修”放行。

## 退出条件

- 候选观察期完成并获得工程、产品和发行三方签字。
- 选定一个 rc 源码状态作为 1.0 基线。
- 1.0 除版本、发布 metadata 和文档外不再接受行为变更。
