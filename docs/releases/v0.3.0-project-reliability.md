# 0.3.0 项目可靠性

> - 发布通道：内部 Alpha
> - 当前状态：planned
> - 内部映射：M2
> - 主要结果：用户项目在重启、异常退出和版本升级后仍可恢复

## 用户结果

用户可以在自己选择的目录创建、打开、保存和另存项目。应用只有在数据真正落盘后才显示“已保存”，异常退出不能把最后一个有效项目覆盖成损坏文件。

## 本版本范围

- 落地唯一 `ProjectDocument` Zod schema 与 `schemaVersion`。
- 建立 `ProjectRepository`、`ProjectSaveCoordinator`、revision、debounce、flush 和 recovery。
- 支持创建、打开、保存、另存为、最近项目和失效路径重新定位。
- 项目目录由用户选择，不把大型项目写入 roaming `userData`。
- 支持首次 `localStorage` 导入，并在迁移前备份原始输入。
- 建立逐版本 `N -> N+1` 迁移和固定 fixtures。
- 从 `App.tsx` 抽离项目切换和持久化职责。
- 建立保存失败、磁盘空间不足、只读目录和未知未来版本的确定行为。

## 非目标

- 本版本不承诺真实资产复制或本地媒体协议。
- 不承诺包含资产的 ZIP 导出。
- 不承诺 MP4 渲染。
- 不允许项目脚本恢复执行。

## 硬验收

- 100 次连续编辑和保存后，磁盘 revision 与最新 UI 状态一致。
- 保存中强制结束应用，重启后恢复最后成功版本或明确提示 recovery 文件。
- 创建、打开、保存、另存为、关闭和项目切换均执行 `flush()`。
- 损坏、旧版和未来版本 fixtures 均有确定结果，原文件不被覆盖。
- 中文、空格、只读和不可写路径测试通过。
- 项目移动或最近项目路径失效时，不创建同名空项目掩盖错误。
- schema round-trip 不丢失规范字段。

## 失败判定

- UI 在落盘前显示“已保存”。
- 旧 revision 的完成事件覆盖新 revision 状态。
- 迁移失败后生成空项目并写回。
- 项目或大型资产默认保存在 `userData`。
- 未知更高版本被当前版本覆盖保存。

## 退出条件

- 项目可靠性集成测试和 Electron 重启测试通过。
- legacy 导入有原始备份和可诊断错误。
- 允许 `0.4.0` 在规范项目根目录中引入真实资产。
