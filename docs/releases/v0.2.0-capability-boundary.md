# 0.2.0 能力边界

> - 发布通道：内部 Alpha
> - 当前状态：planned
> - 内部映射：M1
> - 主要结果：安装版对每项能力给出真实、安全且一致的结果

## 用户结果

用户看到的按钮、状态和错误必须反映真实能力。安装版不能依赖未启动的本地 Web 服务，也不能在失败时返回示例 URL、模拟日志或假成功。

## 本版本范围

- 建立 `AppCapabilities` 与 Web/PC composition root。
- 为 Projects、Assets、Media、Exports、AI、Diagnostics 定义共享 Result、ErrorCode 和 schema。
- 建立窄、类型化 Preload/IPC，Main 再次校验 sender 和 payload。
- 把安装版业务调用从 `/api/*` 迁到 PC adapter 或明确标记 unsupported。
- 明确 Express 只承担 Web 与受控 AI 服务职责。
- 建立 CSP、导航、外链、权限和 IPC sender 安全基线。
- 移除 `new Function`、`eval` 和项目脚本执行路径。
- 提供最小白名单条件 AST 与声明式动作；暂不支持的 legacy 插件明确禁用。
- 从正式工作区隐藏或明确标注原生编译、FFmpeg、OSS 等研发仿真入口。

## 非目标

- 不实现用户项目目录和可靠保存。
- 不复制本地资产到项目目录。
- 不实现真实 ZIP、DOCX 或 MP4 导出。
- 不实现任意 JavaScript 插件兼容。

## 硬验收

- 当前 React UI 在 dev 和 packaged 模式启动。
- Renderer 无 Node 全局，不能访问通用 `ipcRenderer`。
- 未知 IPC、非法 payload、未知 sender 被拒绝并记录稳定错误码。
- 同一合法条件或动作 fixture 在 Web/PC 得到相同结果。
- unsupported 能力显示真实限制，不返回 mock 成功。
- 安装版不需要 Express 才能启动或判断能力可用性。
- 静态检查证明产品代码不存在任意脚本执行入口。
- 每个 capability 有 Web、PC 或 unsupported 的 contract test。

## 失败判定

- 组件直接新增 `window.cinePlayStudio`、Node API 或桌面专用 fetch 分支。
- 项目数据仍能触发 JavaScript 执行。
- 网络或二进制失败后 UI 仍显示“成功”。
- packaged 行为只能用 Web/dev 证据证明。

## 退出条件

- 所有能力入口完成真伪分类。
- 安全与 adapter contract tests 通过。
- 允许 `0.3.0` 在稳定能力接口上实现项目存储。
