# 0.1.0 桌面发行底座

> - 发布通道：内部 Alpha
> - 当前状态：active
> - 内部映射：M0
> - 主要结果：团队能重复构建、安装并启动同一套安全 Electron 编辑器底座

## 用户结果

该版本只证明 Windows 桌面壳和打包链路成立。内部测试人员可以安装并打开现有编辑器界面，但不能把项目存储、资产导入、媒体处理或导出视为正式桌面能力。

## 已确认基线

- React 编辑器 UI 保持可启动。
- Electron 使用隔离 Renderer、窄 Preload API 和受限导航。
- 可以生成 unpacked 与 NSIS 安装包。
- 打包后的 FFprobe 可以处理中文和空格路径。
- 技术 ADR 已确定项目目录、规范 schema、脚本策略和 Web/PC 边界。

## 当前证据状态

- [M0 PM 恢复验收](../orchestration/sessions/m0-pm-acceptance-01.md)记录了 dev、packaged、安装器、FFprobe 和 M0-F legacy lint closure 的恢复验收，当前结论为 `verified`。
- [M0 桌面基线任务卡](../orchestration/tasks/m0-desktop-baseline.md)已将 M0 各子门禁标记为 `verified`；全量 lint、typecheck、format、tests、build 和差异检查均已通过。
- 已验证的 M0 变更已形成提交 `a80d91b`；当前控制面尚待完成提交复核与关闭记录。在控制面放行前，本卡继续保持 `active`，M1 继续关闭。
- 最终证据必须使用 [发布证据模板](release-evidence-template.md) 汇总，不能用分散的成功片段代替整版结论。

## 本版本范围

- 固定 Node、Electron、Vite 和 electron-vite 构建关系。
- 建立 Main、Preload、Renderer 最小入口。
- 建立 Windows NSIS 和媒体二进制 staging。
- 建立 typecheck、lint、format、unit、build 门禁。
- 记录安装包、启动时间、内存、hash 和 packaged FFprobe 证据。
- 清理当前全仓 lint 基线，不改变运行时行为。

## 非目标

- 不迁移 `localStorage`。
- 不实现真实本地资产复制。
- 不实现项目保存、恢复或迁移。
- 不实现真实 FFmpeg 渲染、OSS、自动更新或插件执行。
- 不用当前安装包对外公开发布。

## 硬验收

```bash
npm ci
npm run typecheck
npm run lint
npm run format:check
npm run test
npm run build
npm run dist:win
node scripts/verify-packaged-ffprobe.mjs
```

还必须验证：

- Dev 与 packaged 窗口均非空且可交互。
- `window.cinePlayStudio.app.getInfo()` 在受信 Renderer 中可用。
- Renderer 没有 Node 全局，Preload 不暴露通用 IPC。
- 安装、启动与卸载 smoke 有可追溯证据。
- lint 为 0，不新增 disable，不削弱规则。

## 失败判定

- 任一硬验收失败。
- 只有开发模式成功，安装包失败。
- 通过修改 lint、TypeScript 或安全配置隐藏问题。
- 把 UI 中的模拟能力登记为 packaged verified。

## 退出条件

- 状态更新为 `verified`。
- M0 所有残余风险有明确关闭版本。
- 控制面明确允许进入 `0.2.0 / M1`。
