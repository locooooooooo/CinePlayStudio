# CineFlow Engine 引擎里程碑版本计划

> 状态：Strategic Track / Draft 1
>
> 上游：[影游创作引擎商业企划书](../product/interactive-cinematic-engine-business-plan.md)
>
> 关系：本文件定义 `E0-E8` 引擎里程碑。它不修改 [正式公开版本路线](index.md) 的现有 SemVer、状态或发布承诺；每个里程碑进入正式版本前仍需产品负责人映射到发布卡。

## 1. 计划原则

1. 每个里程碑只承诺一个用户结果。
2. Web、PC Player、Android 不是并行首发目标，必须复用同一 Runtime 逐步推进。
3. 任何跨端声明都要求对应目标环境的真实构建与 smoke。
4. 媒体生成、云协作、市场和分发平台不进入 E0-E8 的首期硬范围。
5. 当前正式路线中的 `0.1.0 / M0`、P0-1、P0-2 控制门禁优先于本计划。

## 3. E0-E3：先建立可信创作底座

### E0 基础事实

- 作用：保持当前桌面基础、控制面和发布证据的真实口径。
- 非目标：不以 M0 壳证据提前宣称项目、媒体、导出或跨端能力。
- 当前事实：仅以当前 `docs/orchestration/**` 与正式版本卡为准。

### E1 能力真实化

- 目标：每个 UI 入口都显示真实 provenance、错误码、支持范围和恢复动作。
- 阻断：任何 mock/fallback 仍可伪装为正式成功。
- 关键任务：`ICE-01` 的依赖准备与现有 P0/M1 能力矩阵对齐。

### E2 项目内核

- 目标：团队把项目交给编辑器后，保存、重开、迁移与异常恢复不伤数据。
- 阻断：项目仍由浏览器多 key 状态或绝对路径引用承担事实来源。
- 关键任务：`ICE-01`。

### E3 本地资产

- 目标：视频、图片、音频和文档以真实字节进入项目目录，并可重开。
- 阻断：远程示例 URL、元数据登记或项目外路径仍被当成导入成功。
- 关键任务：`ICE-02`。

## 4. E4-E7：把同一项目推向多端

### E4 L1 创作与互动 Runtime

- 范围：单主视觉、单 BGM、单 SFX、单字幕、选择、变量、双路径预览、声明式 evaluator。
- 非目标：完整剪映、多轨专业剪辑、完整 MP4 后期或任意脚本插件。
- 任务：`ICE-03`、`ICE-04`、`ICE-05`。

### E5 Web Build

- 范围：从已验证 project revision 生成静态互动包，浏览器按 manifest 播放并保存最小状态。
- 非目标：任意托管、CDN、观众社区或平台分发。
- 任务：`ICE-06`。

### E6 PC Player

- 范围：用同一 Runtime 在支持的 Windows 环境运行 Web 构建包，提供离线存档、诊断与受控文件能力。
- 非目标：编辑器功能、自动更新、任意本地文件访问。
- 任务：`ICE-07`。

### E7 Android Alpha

- 范围：在固定 Android 版本和设备矩阵上封装同一 Runtime，验证全屏、返回键、音频焦点、存档与资源加载。
- 非目标：全机型支持、后台下载、云端更新、性能泛化承诺。
- 任务：`ICE-08`。

## 5. E8：Studio Beta 与商业门禁

E8 不是“做更多功能”，而是证明产品可被真实团队独立使用：

- 至少 3 个设计合作团队带入真实且获授权的样本。
- 至少 2 个团队愿意为下一项目付费，且付款理由是可复用产品价值。
- 支持矩阵内的构建、恢复、交接和错误处理可由非作者完成。
- 定制服务、培训、订阅与 AI 用量分账，不把人工代做算作 ARR。

关键任务：`ICE-09`。

## 6. 版本升级规则

每个 E 里程碑需要同时通过：

1. 范围冻结与明确非目标。
2. 受限实现与自动化测试。
3. 目标环境 smoke 和固定构建产物。
4. 独立验收或外部用户证据。
5. 版本卡、已知问题、回退方式与支持矩阵更新。

任何一项缺失时，里程碑只能停留在 `planned`、`active`、`blocked` 或 `dev_verified`，不能升级为可收费、可发布或跨端已支持。
