# GameEditor 核心用户旅程验收矩阵

> task_id: `T04`
> status: `prepared`
> stage: 准备阶段；不是产品实现、发布验证或真实用户验收
> owner: 产品经理 + QA
> dependency: `T03` 首个垂直模板规格；`T03` 依赖 `T02` ICP 访谈执行与需求证据
> changed_scope: 仅本文档

## 1. 目的与当前边界

本矩阵把“剧本到交付”拆成可以由 QA 执行、记录和复核的步骤。每个步骤都必须同时记录成功、失败、取消和恢复结果；没有用户完成条件、失败判定或恢复证据的步骤不得关闭。

本文件是准备期验收脚本草案，不代表任何能力已经实现。当前不填入 T02 的访谈结果、T03 的模板名称、节点数据、媒体样本、授权结论或用户反馈；这些都是待输入，不得用作者演示、示例项目或文件存在替代。

### 1.1 当前控制面边界

| 边界 | 当前事实                                                                                                               | 对本矩阵的影响                                                                     |
| ---- | ---------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| M0   | 编排控制面仍处于 `M0 commit closeout`；M0 桌面基线在控制面中有已验证/部分结果记录，但 submission commit 仍待完成并验证 | T04 只能准备验收规格和 fixture 设计，不能据此声明产品闭环可用                      |

### 1.2 证据层级

证据层级是互相独立的门槛，不是同一结果的不同叫法。每次执行必须记录版本、运行方式、fixture 或真实项目来源、操作者、时间、日志/截图路径和结果状态。

| 代码 | 证据层      | 可以证明                                                                        | 不能证明                                                       |
| ---- | ----------- | ------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| `M`  | `mock`      | 验收脚本字段、协议形状、正反 fixture、错误码映射是否可执行                      | 产品真实能力、真实文件 I/O、安装版行为、用户价值或真实用户完成 |
| `D`  | `dev`       | 当前开发环境中可重复的技术行为、状态转换和诊断输出                              | 安装包行为、干净机器兼容性、发布质量或外部用户可独立完成       |
| `P`  | `packaged`  | 指定安装包/发布构建在目标机器上的技术行为、版本和输出                           | 真实客户项目交付、外部用户接受、付费价值                       |
| `R`  | `real-user` | 合格外部团队使用自有且获授权的剧本/媒体，脱离作者接管完成步骤，并留下可复核记录 | 仅凭作者现场演示、内部样例或产品团队代操作得到的结论           |

文件、截图、录屏、demo、mock 日志和示例项目都是证据载体，不会自动成为 `R`。只有 `R` 层能够支持“真实用户验收”；`M`、`D`、`P` 不能互相升级或替代 `R`。

### 1.3 失败码约定

下表各步骤中的 `CJ-*` 是 T04 准备期建议码，不是当前产品已经存在的运行时错误码。T06 能力真实性矩阵关闭前不得把它们写入产品、日志或对外文档；实际实现应统一码值、严重级别、用户文案和诊断字段。

每个失败结果至少要记录：建议码或实际码、发生阶段、版本/构建、输入 fixture 或项目标识、是否产生部分输出、恢复动作、恢复后数据 revision，以及证据层 `M/D/P/R`。

## 2. 执行前置与统一通过条件

### 2.1 执行前置

正式执行前，QA 必须补齐以下输入；缺任一项时只能执行 `M` 层结构演练，不能宣称核心旅程通过：

- T02：已脱敏的 ICP 需求证据、目标团队角色和反例；当前为未满足的准备期输入。
- T03：冻结的 5-8 场景垂直模板规格、节点/分支/变量/资产清单、完成路径和授权说明；当前为未满足的准备期输入。
- 版本与构建：版本号、commit 或发布包 hash、运行方式（`mock`/`dev`/`packaged`）。
- 样本：剧本、项目包、视频/音频/字幕及字体的来源、许可/授权状态、hash 和可复现路径；没有授权样本时不得开展 `R`。
- 角色：创作者、叙事/分支设计、媒体/资产负责人、QA、交接接收人；同一人兼任时必须在记录中说明。

### 2.2 统一通过条件

单步通过必须满足：用户角色能够按照操作完成目标；成功输出可观察且可复现；失败有明确码和原因；取消不会产生假成功或破坏已保存状态；恢复能回到最后一次明确成功状态或给出不覆盖原项目的处置；证据层达到该步骤声明的层级。

整条旅程只有在所有步骤完成、失败与取消案例均可复现、重开后数据和资产状态符合预期、健康检查结果可解释、导出包可由接收人重开时，才可以进入真实用户验收评审。单个文件存在、页面能打开或 demo 能播放都不满足该条件。

## 3. 核心用户旅程矩阵

### CJ-01 创建项目

- **前置条件：** T03 已冻结项目 schema、最小剧本输入和完成路径；用户有可写项目目录；当前 T03 输入未满足，故只能准备脚本或执行 `M` 层演练。
- **用户角色：** 创作者/叙事设计师；QA 负责记录，不代替用户完成。
- **操作：** 在指定版本中选择“新建项目”，填写项目名称和位置，选择经 T03 批准的空白或模板入口，确认创建；记录项目标识、schema 版本和初始 revision。
- **成功：** 只创建一个可识别项目；初始文档、目录边界和 schema 可读取；用户能看到下一步输入位置；没有隐式脚本执行或假成功链接。
- **失败：** 无效、无权限、重复或不可写路径被显式拒绝；不留下不可识别的半成品项目；记录 `CJ-PROJ-001`（位置不可用）或 `CJ-PROJ-002`（名称/锁冲突）。
- **取消：** 在确认前取消创建，既不产生新项目，也不修改已有项目；记录取消发生点和 UI/日志状态。
- **恢复：** 用户可改用已确认可写的位置重试；若已产生部分目录，只能由受控清理/回滚流程处理，不能覆盖同名已有项目；记录恢复后的项目标识和 revision。
- **失败码/证据类型：** 建议码 `CJ-PROJ-001/002`；结构演练可用 `M`，技术行为要求 `D`，安装版要求 `P`，独立外部完成才记 `R`。
- **是否依赖尚未实现能力：** 是。依赖 M1 项目目录、唯一 schema、创建/锁定和真实磁盘写入；同时依赖未满足的 T03 模板输入。

### CJ-02 导入项目

- **前置条件：** 有经 T03 认可且已授权的项目包、manifest/schema 版本、资产清单和目标目录；导入前已有项目必须可区分；当前无可引用的真实 T03 包。
- **用户角色：** 创作者或项目接收人；QA 记录源包 hash、导入目标和权限。
- **操作：** 选择“导入项目”，指定项目包或目录，预览 manifest、版本和资产缺失提示，确认导入；不允许通过任意脚本补齐内容。
- **成功：** 项目标识、节点、分支、变量、资产引用和版本信息与源包一致；导入过程不会覆盖无关已有项目；资产缺失、路径变化和授权状态均可见。
- **失败：** 损坏包、缺 manifest、未知/未来版本、路径越界、权限失败或资产缺失被分类拒绝；记录 `CJ-IMPORT-001`（包结构无效）或 `CJ-IMPORT-002`（版本/资产不兼容），不得返回模拟成功。
- **取消：** 在确认导入或复制前取消，目标目录和已有项目不改变；已开始的临时文件不能被当作正式项目。
- **恢复：** 用户可选择有效包、修复授权/路径后重新导入；旧版需走有版本记录的迁移；未知未来版只能只读或拒绝，不能覆盖原包；记录恢复前后 hash/revision。
- **失败码/证据类型：** 建议码 `CJ-IMPORT-001/002`；`M` 只能验证 manifest fixture，`D` 验证本机导入，`P` 验证安装版，`R` 需接收人使用真实授权项目包。
- **是否依赖尚未实现能力：** 是。依赖 M1 项目导入、schema 校验、迁移/只读策略、资产路径恢复和真实文件复制/引用；依赖 T03 包与 T02 真实场景输入。

### CJ-03 生成场景

- **前置条件：** 已创建或导入项目；存在 T03 批准的剧本/大纲格式和场景生成规则；生成范围、预期场景数和人工确认点已定义；当前 T03 规则未冻结。
- **用户角色：** 编剧/叙事设计师；QA 检查生成结果是否可追溯，不把生成结果直接视为成稿。
- **操作：** 导入或粘贴剧本/大纲，选择生成范围，执行生成，查看候选场景、入口/出口、变量和待确认项，明确点击采用或放弃。
- **成功：** 生成结果落入声明式项目 schema；每个场景有稳定 ID、入口/出口和来源定位；不执行任意 JavaScript；用户能修改或放弃候选结果。
- **失败：** 输入无法解析、歧义无法确认、生成超时、schema 校验失败或服务不可用时显式失败；记录 `CJ-SCENE-001`（输入/结构无效）或 `CJ-SCENE-002`（生成不可用/超时），不得将半成品标为完成。
- **取消：** 用户在生成或确认阶段取消，未采用的候选不改变正式项目；若已有正式项目 revision，必须保持不变。
- **恢复：** 缩小范围、修订输入、改用人工声明式录入或重试；保留最后一次成功 revision 和失败上下文，不要求用户重建整个项目。
- **失败码/证据类型：** 建议码 `CJ-SCENE-001/002`；`M` 验证候选结构 fixture，`D` 验证本地生成/回退，`P` 验证安装版，`R` 需真实团队以自有授权剧本独立确认生成结果。
- **是否依赖尚未实现能力：** 是。依赖场景生成/导入能力、schema 校验、可追溯来源和安全的声明式表示；依赖 T03 规则，不能用 AI demo 或示例文本替代。

### CJ-04 绑定分支

- **前置条件：** 场景节点已存在；T03 已定义选择、条件、变量和结局；分支图有预期入口/出口和最小完成路径；当前 T03 分支表未满足。
- **用户角色：** 叙事设计师/策划；QA 复核可达性和失败案例。
- **操作：** 为场景添加选择，绑定条件/变量和后继节点，配置结局，保存草稿后运行结构校验；不得通过脚本实现条件或动作。
- **成功：** 每个选择指向有效节点；条件引用存在且可解释；至少有一条从入口到结局的路径；变更可定位到节点、条件和 revision。
- **失败：** 悬空引用、不可达节点、无出口节点、循环导致无法结局或条件引用不存在时显式标记；记录 `CJ-BRANCH-001`（引用断链）或 `CJ-BRANCH-002`（不可达/无结局）。
- **取消：** 放弃本次分支编辑，草稿不覆盖最后一次成功 revision；取消结构检查不改变项目图。
- **恢复：** 跳转到错误节点修复引用、条件或出口，重新检查并记录前后问题数；无法修复时导出诊断摘要，不允许静默删除节点。
- **失败码/证据类型：** 建议码 `CJ-BRANCH-001/002`；`M` 验证正反分支 fixture，`D` 验证编辑器状态，`P` 验证安装版，`R` 需真实团队按 T03 路径独立完成并理解结果。
- **是否依赖尚未实现能力：** 是。依赖声明式分支模型、图编辑/校验和变量条件能力，且依赖未冻结的 T03 分支图；也受 M1 工程实现门禁约束。

### CJ-05 绑定素材

- **前置条件：** 场景/轨道已确定；有获授权的视频、音频、字幕或字体样本，含格式、大小、hash、许可和来源记录；当前没有可写入本矩阵的真实客户素材。
- **用户角色：** 媒体/资产负责人或创作者；QA 检查路径、许可和失败清理。
- **操作：** 选择复制或引用策略，添加素材，绑定到场景/轨道，查看时长、格式、路径、hash、许可状态和预览入口，确认绑定。
- **成功：** 绑定项指向可读取且支持的素材；路径边界和许可状态可见；移动或重开策略有明确结果；没有未报告的占位资源或假预览。
- **失败：** 文件不存在、无权限、格式不支持、hash 不符、路径越界、许可未确认或预览解码失败时显式拒绝/标记；记录 `CJ-ASSET-001`（文件/权限）或 `CJ-ASSET-002`（格式/许可）。
- **取消：** 在复制、引用或确认绑定前取消，不留下正式悬空引用，不改变原绑定；中断复制不得冒充完整素材。
- **恢复：** 重新选择授权素材、修复路径或切换受支持格式后重新绑定；原项目保留最后成功引用；记录恢复后的 hash 和缺失项清单。
- **失败码/证据类型：** 建议码 `CJ-ASSET-001/002`；`M` 只能用路径/格式 fixture，`D` 验证本机文件行为，`P` 验证安装包，`R` 需外部团队使用自有授权媒体。
- **是否依赖尚未实现能力：** 是。依赖 M1 本地资产导入/引用、路径边界、hash、许可字段和真实媒体预览；不能用内置示例素材代替真实素材证据。

### CJ-06 路径预览

- **前置条件：** 至少一条已通过结构检查的入口到结局路径；分支、素材和字幕/音频轨道已绑定；预览运行方式、起始节点和选择记录已定义。
- **用户角色：** 叙事设计师、QA 或交接前审阅人；真实验收时由外部团队自行选择路径。
- **操作：** 选择起始节点，运行路径预览，按选择进入分支，观察场景、视频、音频、字幕和路径记录，记录首次成功预览耗时与阻塞。
- **成功：** 选定路径按预期顺序到达结局；节点、媒体、音画和字幕状态可观察；相同输入可复现；预览不会修改正式项目数据。
- **失败：** 路径不可达、节点无出口、素材缺失、解码/渲染失败或路径状态不一致时停止并分类；记录 `CJ-PREVIEW-001`（路径结构）或 `CJ-PREVIEW-002`（媒体/渲染）。
- **取消：** 用户停止预览或返回编辑，预览进程可结束，正式项目和最后成功保存不改变；取消不应被报告为预览成功。
- **恢复：** 返回对应节点或健康检查结果修复结构/资产，重新运行同一路径；若只能跳过资源，必须明确标记未通过，不得生成假完整预览。
- **失败码/证据类型：** 建议码 `CJ-PREVIEW-001/002`；`M` 只验证路径状态机，`D` 验证开发环境预览，`P` 验证安装版，`R` 需真实用户独立完成一次路径审查。
- **是否依赖尚未实现能力：** 是。依赖真实路径预览、渲染适配器和本地媒体播放；当前 M1 仍关闭，不能把 demo 播放或截图当作交付证据。

### CJ-07 保存

- **前置条件：** 项目已创建/导入并完成一次可识别编辑；已有项目标识、schema 和最后成功 revision；保存目标可写或已有受控恢复策略。
- **用户角色：** 创作者；QA 注入可记录的锁、权限、磁盘或中断条件。
- **操作：** 修改节点、分支或资产绑定，执行保存，等待明确成功状态，记录 revision、磁盘文件 hash/大小和保存耗时；必要时执行受控中断案例。
- **成功：** 成功提示对应实际落盘 revision；重读项目可得到相同结构和引用；保存队列不丢更新，不产生半成品正式文件。
- **失败：** 写锁、无权限、磁盘不足、序列化失败或保存中断被显式报告；记录 `CJ-SAVE-001`（目标不可写）或 `CJ-SAVE-002`（序列化/中断）；不得把内存状态当成已保存。
- **取消：** 在保存队列提交前取消，正式项目保持最后成功 revision；提交后不可安全取消时必须显示进行中并提供结果，不得伪造取消成功。
- **恢复：** 重试到新目标、释放锁或从恢复文件回到最后成功 revision；恢复不能覆盖原始项目，需记录 revision 链和数据差异。
- **失败码/证据类型：** 建议码 `CJ-SAVE-001/002`；`M` 验证保存协议 fixture，`D` 验证本机真实写入，`P` 验证安装版，`R` 需真实项目在用户环境下重复编辑并核对磁盘结果。
- **是否依赖尚未实现能力：** 是。依赖 M1 项目存储、revision、原子/可恢复保存、锁和损坏保护；完整可靠性还依赖后续 T07，不能由当前 localStorage 或 demo 状态直接推出。

### CJ-08 重开

- **前置条件：** 已有一次明确成功保存的项目；关闭/重启边界、项目路径、最近成功 revision 和资产位置已记录；重开测试不能只打开当前内存页面。
- **用户角色：** 创作者或项目接收人；QA 可执行崩溃/强制结束后的受控恢复案例。
- **操作：** 关闭项目或退出应用，重新启动指定版本，打开项目，核对 revision、场景、分支、素材引用、字幕/音频和未完成保存提示。
- **成功：** 重开得到最近一次成功保存的结构；项目状态、资产路径和版本提示一致；如果存在未完成保存，行为明确且不覆盖最后成功版本。
- **失败：** 文件损坏、schema 未知、项目移动导致路径失效、迁移失败或恢复文件不可用时显式报告；记录 `CJ-OPEN-001`（文件/数据损坏）或 `CJ-OPEN-002`（路径/版本不兼容）。
- **取消：** 在文件选择、迁移确认或恢复确认阶段取消，不覆盖原项目，不丢弃最后成功版本；取消后能回到项目列表或安全入口。
- **恢复：** 选择最后成功版本、受控备份或只读打开；修复资产路径后重新检查；未来版本只读/拒绝打开，不原地覆盖；记录恢复结果和是否需要人工介入。
- **失败码/证据类型：** 建议码 `CJ-OPEN-001/002`；`M` 验证损坏/版本 fixture，`D` 验证本机重启，`P` 验证安装版，`R` 需外部接收人不依赖作者完成重开。
- **是否依赖尚未实现能力：** 是。依赖真实磁盘保存、恢复、迁移、项目移动后的路径策略和安装版启动；依赖 T07 可靠性规格，当前 M1 guard 下不得实现。

### CJ-09 健康检查

- **前置条件：** 项目包含可检查的场景、分支、变量和资产引用；T03 已定义预期路径；T07/T10 的规则、严重级别、正反 fixture 和修复建议已批准；当前 T07/T10 输入未满足。
- **用户角色：** 叙事设计师或 QA；修复人应与检查人分开记录，避免只由作者口头判定。
- **操作：** 运行健康检查，查看断链、不可达节点、无出口节点、未绑定资产、未使用变量、未知条件引用、结局覆盖和时序冲突，定位到节点/轨道/变量并修复后重新检查。
- **成功：** 每条已定义规则都有可重复结果；问题有位置、严重级别和建议；修复后问题数按预期下降；检查过程不执行用户脚本且不修改项目内容。
- **失败：** 检查器自身崩溃、规则漏报/误报无法解释、结果不可重复或定位信息缺失时失败；记录 `CJ-CHECK-001`（检查执行）或 `CJ-CHECK-002`（结果不完整/不可复现）。
- **取消：** 检查中取消或关闭结果，项目内容和最后成功 revision 不改变；部分检查结果只能标记为未完成。
- **恢复：** 重试固定 fixture，修订项目后重新运行；规则暂不支持时输出明确 `unsupported`，不能以绿色通过替代未知；保存检查报告版本和输入 hash。
- **失败码/证据类型：** 建议码 `CJ-CHECK-001/002`；`M` 验证规则正反 fixture，`D` 验证检查执行，`P` 验证安装版，`R` 需真实用户能够根据报告自行修复并复查。
- **是否依赖尚未实现能力：** 是。依赖 T10 规则集、T07 项目 schema/资产状态和真实健康检查实现；当前只能准备规则、fixture 和脚本，不得宣称已通过。

### CJ-10 导出

- **前置条件：** 项目已保存且健康检查结果达到导出门槛；已确认项目包、媒体输出、字幕/音频、字体、分辨率、输出目录和许可清单；真实 MP4 输出要求对应版本门禁关闭。
- **用户角色：** 创作者或交付负责人；QA 核对输出检查和失败清理。
- **操作：** 选择项目包或媒体输出类型，确认输出路径和交付清单，执行导出，观察进度、取消入口、输出文件 hash/大小/时长和检查结果。
- **成功：** 输出类型与选择一致；项目包可被接收方识别，真实媒体输出可播放且字幕/音频/时长正确；输出清单、版本和 hash 完整；无未声明依赖。
- **失败：** 未通过健康检查、输出路径不可写、格式/字体不支持、媒体处理失败、取消或崩溃时显式分类；记录 `CJ-EXPORT-001`（导出/媒体）或 `CJ-EXPORT-002`（路径/取消清理）；失败不得留下可被误交付的正式目标文件。
- **取消：** 用户取消导出后，任务状态明确为 cancelled；临时文件可识别且按策略清理，正式目标文件不被替换；取消不计入成功输出。
- **恢复：** 修复项目/路径/媒体后从最后成功保存版本重试；对失败输出做完整性检查，必要时另选目标；记录是否恢复成功和旧输出是否保留。
- **失败码/证据类型：** 建议码 `CJ-EXPORT-001/002`；`M` 只能验证 job contract，`D` 验证开发环境，`P` 必须验证安装版真实输出，`R` 必须使用外部团队自有场景并交付可检查文件。
- **是否依赖尚未实现能力：** 是。依赖项目包导出、真实媒体/FFmpeg 输出、取消、失败清理和输出检查；M0/M1 门禁关闭时不得实现，不能用模拟日志或示例 URL。

### CJ-11 交接

- **前置条件：** 导出已产生可核对的项目包/媒体和 manifest；交接人、版本、许可、支持格式、已知问题、恢复说明和接收路径已确定；交接人不应由作者代替完成全部操作。
- **用户角色：** 交付负责人/创作者和项目接收人；QA 观察接收人从干净工作目录完成核对与重开。
- **操作：** 发送项目包、媒体、清单和说明，接收人校验 hash/版本/许可，按文档导入或打开项目，重跑至少一条路径并确认输出/问题记录。
- **成功：** 接收人能够识别版本、打开或导入项目、找到所需素材、理解已知问题并复现预期路径；交付包不依赖作者机器、临时 URL、未声明字体或口头补充。
- **失败：** 缺 manifest/素材/许可，hash 不符，接收人无法重开，路径依赖作者本机或说明不足时拒绝交付；记录 `CJ-HANDOFF-001`（交付包不完整）或 `CJ-HANDOFF-002`（接收方无法重开/复现）。
- **取消：** 在交付确认前取消发送，原项目和已确认输出不改变；部分上传/复制物必须标记为临时，不得让接收人误用。
- **恢复：** 补齐清单或素材、修复包内路径、重新导出并更新版本/hash；接收人重新核对，直到问题关闭或明确转为 `blocked`，不得以作者远程代操作掩盖失败。
- **失败码/证据类型：** 建议码 `CJ-HANDOFF-001/002`；`M` 验证清单字段，`D` 验证本地接收流程，`P` 验证安装版交接，`R` 必须由真实外部接收人独立完成并留下交付记录。
- **是否依赖尚未实现能力：** 是。依赖项目包、路径迁移、真实输出、文档/支持和接收方重开能力；依赖 T02 的真实工作流证据以及后续 T07-T09，当前不能声称可交付。

## 4. 取消、失败与恢复的统一判定表

| 情形 | 必须观察到的结果                                                             | 不通过的表现                                   |
| ---- | ---------------------------------------------------------------------------- | ---------------------------------------------- |
| 成功 | 实际产物、状态、revision 或路径结果与操作目标一致，且可由指定证据层复核      | 只有按钮反馈、截图、demo 或内存状态            |
| 失败 | 用户看到可理解的失败状态；建议码/实际码、原因、阶段和部分输出状态可追踪      | 静默失败、返回假 URL、显示成功但没有真实产物   |
| 取消 | 取消状态可区分于成功/失败；正式项目和最后成功产物不被破坏                    | 取消后仍生成正式目标文件，或无法知道是否已提交 |
| 恢复 | 可回到最后成功 revision，或以不覆盖原项目的方式重试/只读打开；恢复结果有证据 | 要求用户重建项目、覆盖原文件、依赖作者现场操作 |

任何步骤发生数据丢失、假成功、不可复现、未授权素材、未知版本被覆盖或任意脚本执行，整条旅程直接 `blocked`，不因其他步骤通过而降级为一般风险。
