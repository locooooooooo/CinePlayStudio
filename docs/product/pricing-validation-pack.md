## 1. 本任务的目标与边界

### 1.1 目标

为产品经理准备一套可直接用于 ICP 访谈、设计合作和付费试点的价格与包装实验材料，验证三件事：

1. 目标客户愿意为什么结果付费，而不是愿意为什么功能点赞。
2. Creator Pro、Team、Studio 三层包装是否对应不同的购买主体、预算来源和交付责任。
3. 客户的付款、续用和转介绍行为是否足以支持后续标准产品收入判断。

### 1.2 非目标

- 本次不确定最终价格、折扣、转化率、ARR 或市场规模。
- 本次不进行真实定价访谈，不新增客户、预算、付款或续用记录。
- 本次不把云协作、平台抽成、独立运行时、云渲染或任意插件执行写入当前商品承诺。
- 本次不把定制开发、人工代做、培训和素材制作费包装成标准软件 ARR。
- 本次不修改产品源码、工程版本状态或 M0/M1 控制面。

## 2. 三类客户的购买结果

价格实验必须先展示客户购买的结果，再展示能力清单。以下结果均为**待验证假设**。

| 包装                | 目标购买者                       | 应购买的结果                                                             | 明确不包含                                                               | 当前工程前置条件                                                                     |
| ------------------- | -------------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------ |
| Creator Pro         | 独立创作者、编剧导演、个人制片人 | 用自己的剧本和素材完成一个可预览的互动样片，并能保存、重开和导出         | 多人实时协作、云同步、平台分发、企业 SLA、无限 AI 用量                   | `0.3.0` 项目可靠性、`0.4.0` 本地资产、`0.6.0` 真实 MP4，且达到 packaged verified     |
| Team                | 2-15 人影游/互动内容团队         | 让编剧、剪辑、策划和制片围绕同一项目交接、评审和复用，减少分支沟通与返工 | 实时共同编辑、无限席位、云端自动备份、平台抽成、未实现的权限能力         | PC MVP、项目包交接、版本历史、评审批注、权限模型和支持流程，不能在这些能力存在前销售 |
| Studio / Enterprise | 制作公司、学校、品牌客户         | 在固定支持边界内批量制作或交付互动内容，并获得部署、培训、模板和支持责任 | 未验证的运行时平台、全托管内容制作、无限定制、观众收入分成和大规模云渲染 | 发行加固、签名/回退、支持矩阵、许可说明、私有部署边界和至少一个真实交付案例          |

### 2.1 结果表达模板

访谈和报价时统一使用以下表达方式：

> 在支持的 Windows 环境中，团队可以把一份剧本和获授权的媒体整理成可点击的分支样片；项目可保存、交接、检查和导出。未实现的云同步、实时协作和平台发布不包含在本次方案内。

如果客户真正要的是剪辑、代制作、平台分发或定制游戏开发，应记录为反例或服务机会，不得强行归入 CinePlayStudio 标准产品价值。

## 3. 三层包装实验卡

### 3.1 Creator Pro 实验卡

**实验假设：** 独立创作者愿意为“从剧本到可预览样片的稳定闭环”按月或按年支付，而不是只为 AI 拆剧本支付。

| 字段       | 实验内容                                                                                         |
| ---------- | ------------------------------------------------------------------------------------------------ |
| 结果承诺   | 单人可以使用自己的项目完成编辑、路径预览、保存/重开和真实输出                                    |
| 价格假设   | `99-199 元/月` 或 `999-1,999 元/年`，仅作访谈锚点，不是价目表                                    |
| 可测试变量 | 月付/年付、单项目上限、AI 用量、模板数量、输出限制、免费体验时长                                 |
| 包含内容   | 本地项目、受支持的本地资产、核心分支编辑、有限 AI 配额、MP4 预览和版本更新                       |
| 不包含内容 | 云同步、实时协作、企业支持、无限 AI、平台分发和人工代做                                          |
| 关键证据   | 当前是否自费购买工具、是否已有真实项目、是否愿意提供素材试用、是否愿意留下付款方式或接受正式报价 |
| 当前状态   | 价格和权益均待 T02 ICP 访谈、T09 真实输出和首批试点验证                                          |

**访谈对照：** 先问客户上一个项目如何完成，再展示结果承诺；不得先展示价格后诱导客户评价功能。

### 3.2 Team 实验卡

**实验假设：** 团队愿意为项目交接、版本可追溯和减少返工支付工作空间或席位费用，但不会为当前尚未实现的实时协作买单。

| 字段       | 实验内容                                                                                     |
| ---------- | -------------------------------------------------------------------------------------------- |
| 结果承诺   | 多角色围绕同一份项目交接和评审，改稿后能知道分支、素材和输出是否仍然有效                     |
| 价格假设   | `699-1,999 元/月/工作空间`，席位数和支持等级作为变量，不是最终报价                           |
| 可测试变量 | 工作空间/月、席位包、年度折扣、项目数、支持响应时间、评审和版本历史                          |
| 包含内容   | 多席位授权、项目交接、版本记录、基础评审流程和产品支持，前提是这些能力已真实可用             |
| 不包含内容 | 实时共同编辑、无限席位、云端资产托管、平台发行、定制功能和观众收入抽成                       |
| 关键证据   | 团队当前是否因分支改稿发生返工、是否已有协作工具预算、谁能批准采购、是否愿意用真实项目做试点 |
| 当前状态   | Team 方案只能做购买逻辑研究；权限和协作未实现前不得销售为现成功能                            |

**访谈对照：** 先确认团队是否确实有多人交接和版本问题，再测试“工作空间”是否比“个人席位”更符合预算归属。

### 3.3 Studio / Enterprise 实验卡

**实验假设：** 制作公司、学校和品牌客户愿意为可控部署、支持责任和模板服务购买年度授权，但这属于高接触销售，不应以个人订阅价格外推。

| 字段       | 实验内容                                                                     |
| ---------- | ---------------------------------------------------------------------------- |
| 结果承诺   | 在明确支持矩阵和交付边界内，团队可以批量制作或交接互动内容，并获得稳定支持   |
| 价格假设   | 年度报价，按部署方式、席位/项目规模、培训、模板和支持等级拆分，不预填金额    |
| 可测试变量 | 本地/私有部署、年度授权、支持响应、培训次数、模板包、项目数量和更新周期      |
| 包含内容   | 许可、安装支持、标准模板、培训、问题响应和版本说明，具体内容需以真实合同为准 |
| 不包含内容 | 全托管制作、无限定制、未经验证的运行时发布、云渲染、平台抽成和第三方素材版权 |
| 关键证据   | 采购主体、法务/安全要求、年度预算流程、部署约束、真实交付项目和续约责任人    |
| 当前状态   | 在 `1.0.0` 支持与发行边界、真实案例和服务成本未验证前，只能做报价结构访谈    |

## 4. 三种报价/包装对照方案

三种方案用于同一目标客户的对照实验，不代表同时上线。

### 方案 A：席位优先

| 项目        | 设计                                                 |
| ----------- | ---------------------------------------------------- |
| 适合验证    | 个人创作者与小团队是否接受订阅心智                   |
| Creator Pro | 单人月付/年付，包含个人项目和真实预览边界            |
| Team        | 工作空间基础费 + 固定席位包，按年付提供折扣          |
| Studio      | 年度许可 + 支持等级，单独报价                        |
| 优点        | 账单简单，适合持续使用和版本更新                     |
| 风险        | 若客户是项目制采购，月订阅可能不符合预算流程         |
| 访谈问题    | 客户目前按人、按工具还是按项目采购？谁拥有席位预算？ |

### 方案 B：项目优先

| 项目        | 设计                                                                   |
| ----------- | ---------------------------------------------------------------------- |
| 适合验证    | 影游和品牌团队是否更愿意为一次明确交付付费                             |
| Creator Pro | 单项目/年度项目包，限制项目范围但不把人工代做混入软件费                |
| Team        | 项目包包含固定成员、版本交接和支持周期                                 |
| Studio      | 多项目年度授权，按项目数或制作规模分档                                 |
| 优点        | 与客户现有制作预算和交付节点更接近                                     |
| 风险        | 可能抑制长期留存，且需要明确定义项目边界和超额规则                     |
| 访谈问题    | 客户更容易批准一笔项目预算，还是持续工具订阅？项目验收由什么结果定义？ |

### 方案 C：年度许可 + 服务分层

| 项目        | 设计                                                          |
| ----------- | ------------------------------------------------------------- |
| 适合验证    | Studio、学校和品牌客户的年度采购与部署需求                    |
| Creator Pro | 不作为主推方案，仅保留个人试用入口                            |
| Team        | 年度工作空间许可，含有限支持和标准模板                        |
| Studio      | 年度软件许可、部署支持、培训和模板服务分开列项                |
| 优点        | 能把软件收入、服务收入和一次性定制清楚分开                    |
| 风险        | 销售周期长，容易把产品变成项目外包；需要强标准化边界          |
| 访谈问题    | 客户能否签年度合同？法务、采购、IT 和内容负责人分别关心什么？ |

### 4.1 对照规则

- 每次访谈最多展示两种方案，避免客户只对排版差异做表面评价。
- 三种方案必须使用相同的核心交付结果，不能通过偷偷增加未实现能力制造偏好。
- 记录客户选择、拒绝、犹豫和要求改价的行为及理由，不能只记录“喜欢方案 A”。
- 未完成 T02 前，方案选择只能记作研究输入；未完成 T09 前，不能把真实输出写进报价承诺。

## 5. 定价访谈脚本

### 5.1 开场说明

```text
我们正在验证一款面向互动影游团队的制作工具，重点是把剧本、分支、素材、预览和交付放在同一份项目中。
今天只想了解你们现在如何完成这类项目、哪里产生返工，以及什么结果值得预算支持。
下面出现的价格和包装都是研究假设，不是正式报价；你可以拒绝回答，不需要提供剧本、媒体或任何敏感信息。
```

### 5.2 核心问题

| 编号  | 问题                                               | 验证假设             | 追问                                         | 证据记录                |
| ----- | -------------------------------------------------- | -------------------- | -------------------------------------------- | ----------------------- |
| `P01` | 过去 12 个月做过几次包含分支或互动选择的项目？     | 客户有真实任务       | 项目长度、场景数、角色和输出是什么？         | 项目事实，不记敏感内容  |
| `P02` | 从剧本到样片目前经过哪些工具和角色？               | 交接链存在           | 哪一步最常等待或返工？                       | 工具链和角色图          |
| `P03` | 最近一次分支改稿造成了什么具体后果？               | 返工是可量化痛点     | 花了多少人天？谁发现问题？                   | 客户描述，标注估算/记录 |
| `P04` | 如何确认所有路径、条件和结局都能走通？             | 质量检查是付费价值   | 是否有固定 checklist 或自动检查？            | 现有流程/缺口           |
| `P05` | 项目换人、换电脑或隔一段时间重开时发生过什么？     | 可靠保存和交接有价值 | 是否丢过版本、素材或配置？                   | 真实事件，不索取文件    |
| `P06` | 现在为剪辑、协作、项目管理或引擎工具支付什么？     | 存在相邻预算         | 是按人、按月、按项目还是一次性？             | 只记区间和采购方式      |
| `P07` | 如果能把剧本变成可点击分支样片，最先想改善哪一步？ | 结果优先于功能       | 这会替代什么人工步骤？                       | 用户原话和替代链        |
| `P08` | 你更容易批准席位订阅、项目包还是年度授权？         | 包装匹配采购流程     | 谁批准，预算来自哪个部门？                   | 决策链                  |
| `P09` | 对 Creator Pro 的价格区间反应如何？                | 个人价格锚点可接受   | 什么条件会让你立刻拒绝？                     | 必须记录行为和原因      |
| `P10` | 对 Team 工作空间方案反应如何？                     | 团队为交接/评审付费  | 需要几人、多久、什么支持？                   | 需求与预算分开          |
| `P11` | 对 Studio 年度许可和服务分层反应如何？             | 企业采购需要年度结构 | 需要哪些法务、部署、培训和 SLA 条件？        | 采购条件                |
| `P12` | 如果今天可以试用，愿意拿哪个真实项目验证？         | 有行动意愿           | 素材是否获授权？何时能开始？                 | 试用承诺与授权状态      |
| `P13` | 什么结果会让你续用或推荐给同行？                   | 续用和传播有价值     | 是节省时间、减少错误、交付成功还是客户认可？ | 明确结果与责任人        |
| `P14` | 哪些需求会让你把它当成定制外包，而不是软件？       | 识别商业边界         | 需要多少定制？是否有第三方替代方案？         | 反例编码                |

### 5.3 价格测试规则

- 先问历史行为和真实项目，再展示结果承诺，最后才展示价格区间。
- 先让客户在方案 A/B/C 中选购买逻辑，再问金额；避免把“价格太高”误判为“需求不存在”。
- 记录四种反应：接受、条件接受、延期、拒绝；每种反应必须带理由和行动证据。
- “我会考虑”“挺有意思”“以后可能需要”属于意见，不得升级为购买意愿。
- 只有报价确认、试点签署、付款或明确采购流程进入高等级证据。

## 6. 异议编码、证据等级与反例

### 6.1 异议编码

| 编码  | 异议                     | 判定方向            | 后续动作                                     |
| ----- | ------------------------ | ------------------- | -------------------------------------------- |
| `O01` | 价格高，但承认结果有价值 | 可能是包装/预算问题 | 测试项目包、年付或缩小范围，不直接降价       |
| `O02` | 只愿意为 AI 拆解付费     | 核心价值未成立      | 追问真实交付和返工，不把 AI 用量变成主产品   |
| `O03` | 需要实时协作/云同步      | 超出当前边界        | 记入 P2 需求，不写入当前报价承诺             |
| `O04` | 更需要代制作或定制功能   | 服务/外包需求       | 单列服务报价，不计入标准 ARR                 |
| `O05` | 不信任本地保存或素材交接 | 产品可靠性缺口      | 等 `0.3.0-0.5.0` 真实证据，不用话术补偿      |
| `O06` | 已有工具能完成           | 替代价值不足        | 追问分支返工、检查和交接成本，允许记录为反例 |
| `O07` | 采购流程太长             | 企业销售周期问题    | 先做设计合作或项目型试点，不假设短期成交     |
| `O08` | 不愿提供真实项目         | 证据不足            | 保留为兴趣线索，不进入 pilot_verified        |

### 6.2 愿付行为证据等级

| 等级 | 证据                                     | 能证明什么       | 不能证明什么            |
| ---- | ---------------------------------------- | ---------------- | ----------------------- |
| `E0` | 泛泛兴趣、口头赞同                       | 话题有吸引力     | 不证明需求、预算或价格  |
| `E1` | 描述过往真实项目和返工事件               | 痛点可能真实     | 不证明愿意购买          |
| `E2` | 说明现有工具支出、预算来源或采购流程     | 存在相邻支付能力 | 不证明会购买 CinePlayStudio |
| `E3` | 要求正式报价、确认试点范围或提交采购信息 | 有明确行动意愿   | 不证明已经付款或可续用  |
| `E4` | 签署付费试点、完成付款、续用或转介绍     | 具备商业验证证据 | 仍需确认规模化和毛利    |

**T05 结论规则：** E0-E2 只能形成研究假设；至少 E3 才能进入付费试点候选；E4 才能支持“已有付费证据”的回调。当前文件没有任何 E3/E4 真实记录。

### 6.3 反例规则

以下情况不得计入正向价格证据：

- 受访者没有真实互动内容项目，只评价概念或界面。
- 受访者愿意支付的是人工代做、定制开发、培训或素材制作。
- 价格反馈来自团队中无法批准预算的人，且没有采购路径。
- 客户认可云协作、平台分发或运行时功能，但这些能力当前未实现。
- 受访者在获得免费服务、关系优惠或现场帮助后表示“愿意购买”。
- 只有浏览、点赞、收藏或口头说“之后需要”，没有后续动作。

```text
批准人:
```

### 7.2 付款判断

只有同时满足以下条件，才可将试点记录为 `paid_pilot`：

- 目标客户有真实项目和明确交付结果。
- 软件能力、版本和不包含项已书面确认。
- 客户授权素材和诊断数据范围已确认。
- 付款主体、金额、付款节点和退款条件已明确。
- 验收不是“作者现场帮客户做完”，而是客户可以依据约定独立完成或确认交付。

### 7.3 续用判断

续用至少需要一项可追溯行为和一项价值证据：

- 行为：续费、追加项目、增加席位、主动要求正式报价或转介绍。
- 价值：减少返工、缩短样片交付、成功完成真实输出、项目交接成功或支持成本下降。

“客户觉得不错但暂时没有项目”应记为 `not_now`，不记为续用；“继续要求定制开发”应单列为服务机会，不直接记为标准产品留存。

### 7.4 ARR 边界

标准 ARR 只包括可重复的软件订阅、年度许可或标准工作空间授权。以下收入必须单独列示，不得混入标准 ARR：

- 一次性定制开发。
- 人工代做一部作品或素材制作。
- 培训、驻场和实施服务。
- 第三方素材、字体、云资源或其他代付成本。
- 一次性迁移、数据清理和特殊格式转换。

## 9. T05 验收与失败判定

### 9.1 验收标准

- 三类客户的购买结果、不包含项和工程前置条件清楚分开。
- Creator Pro、Team、Studio 均有独立的价格实验卡，且标明假设而非最终价格。
- 至少 3 种报价/包装方案可直接用于访谈或试点报价对照。
- 至少 10 个定价访谈问题具备假设、追问和证据记录方式；本包实际提供 14 个。
- 异议编码、E0-E4 证据等级和反例规则可以支持后续 PM 复盘。
- 报价字段、付款/续用判断和标准 ARR 边界可以直接复制到试点流程。
- T02、T09 和工程能力依赖明确，未把未实现能力写成当前商品。
- 文件只新增在 `docs/product/pricing-validation-pack.md`，Markdown 结构和 `git diff --check` 通过。

### 9.2 失败判定

- 出现任何声称价格已经验证、已有客户付款、已有转化率或已有续费的数据。
- 把云同步、实时协作、平台分发、运行时授权或任意插件执行写入当前套餐承诺。
- 把定制开发、人工代做或培训收入记为标准 ARR。
- 访谈问题只问“喜不喜欢”，没有真实项目、预算和行动证据。
- 未完成 T02/T09 便填写最终价格、真实输出能力或商业成功指标。
- 修改了任务规定外的文件，或在仓库中写入客户隐私和原始素材。

### 9.3 残余风险

- 价格区间仍是内部假设，尚未经过真实 ICP 访谈。
- 三层包装可能需要按客户采购流程重组，不能由单次访谈决定。
- Team/Studio 价值依赖后续协作、支持和部署能力，当前只能验证购买逻辑。
- 试点合同若没有严格拆分软件与服务，后续 ARR 和毛利会失真。
