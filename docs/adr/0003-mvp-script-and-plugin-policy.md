# ADR-0003：MVP 禁止任意脚本与插件执行

- 状态：Accepted
- 日期：2026-07-13
- 决策阶段：M0-A
- 影响阶段：M1、M2、M4

## Context

当前原型使用 `new Function` 执行条件、动作并检查插件代码。桌面版项目可以来自下载、共享、旧浏览器存储或拖入文件，必须将其中的脚本、表达式和插件描述视为不可信输入。Electron 同时具备本地文件、网络和子进程能力，一旦不可信代码跨入 Renderer、Preload 或 Main，影响范围将显著高于普通网页。

Node `vm` 官方不承诺安全隔离。冻结 global、提示用户信任、CSP 或把脚本放进另一个 Renderer，也不能单独构成可执行第三方代码的安全边界。

## Decision

PC MVP 和 Web MVP 都不执行项目携带的任意 JavaScript。该禁令覆盖运行、导入、语法检查、预览、导出和后台任务，不因文件来源、签名文本或用户点击“信任”而放宽。

具体规则如下：

- 禁止 `new Function`、直接或间接 `eval`、动态脚本标签、远程代码加载，以及用 Node `vm` 执行项目内容。
- 条件采用版本化、可解析的白名单表达式，只允许比较、布尔运算和变量读取。持久化表示是经过 schema 校验的 JSON AST；若编辑器接受文本输入，必须先解析为 AST，解析失败时不得保存为可运行条件。
- 动作采用版本化声明式命令，例如 `setVariable`、`addVariable` 和 `goToScene`。命令名、参数类型、目标范围和执行步数均由 schema 与解释器白名单约束。
- 条件与动作解释器不提供文件系统、网络、DOM、进程、环境变量、计时器或动态模块能力。
- `ProjectDocument.pluginDescriptors` 仅保存静态元数据和禁用状态，不包含源码、函数字符串或可执行入口。
- legacy 项目中的插件代码可以作为禁用迁移原件隔离保留，并记录 hash、来源和迁移结果；它不进入规范 `pluginDescriptors` 的可执行路径，不编译、不预览、不传给解释器。
- 生产 CSP 禁止 `unsafe-eval`，Renderer、Preload 和 Main 不暴露通用代码执行接口。

未来若需要插件系统，必须脱离 PC MVP 单独立项，先完成威胁模型、权限模型、资源预算、撤销与更新机制，再通过新 ADR 选择受限 DSL、QuickJS/WASM 或独立低权限进程。该未来决策不能追溯性地扩大本 ADR 下 MVP 项目的权限。

## Consequences

- MVP 无法运行现有任意 JavaScript 插件；导入后必须向用户明确显示“已禁用”，不能伪装为兼容成功。
- 白名单 AST 和声明式命令比 JavaScript 灵活性低，但可序列化、可迁移、可静态校验，也更容易设置执行步数和性能预算。
- Web 与 PC 使用相同声明式语义，避免同一项目在两个运行时产生不同安全行为。
- 需要为旧条件、动作和插件数据编写显式迁移或拒绝策略。
- 插件能力推迟到独立项目，PC MVP 的时间与安全边界更清晰。

## Rejected Alternatives

### 使用 Node `vm` 并冻结 global

拒绝。`vm` 不是不可信代码的安全隔离边界，且超时、内存、原生模块和宿主对象泄漏风险无法由冻结 global 解决。

### 用户确认“信任此项目”后执行脚本

拒绝。用户无法有效审计项目代码，社工提示也不能替代权限隔离、资源限制和更新治理。

### 仅依赖 CSP 阻止危险代码

拒绝。CSP 是纵深防御，不是脚本解释器或 Main 进程代码执行的授权模型。

### 在独立 Renderer 中执行插件

拒绝作为 MVP 方案。独立窗口仍需严谨的进程隔离、IPC 能力控制、资源限制和生命周期治理，不能自动视为沙箱。

### 保留脚本，只在导出或预览时执行

拒绝。导出和预览同样处理不可信输入，并可能接触文件、网络和长任务资源。

## Verification Implications

本 ADR 在 M0 只形成决策证据，不提前实现 M1/M2 的解释器或迁移器。

- 对产品自有的 `src/**`、`electron/**` 和 `shared/**` 建立静态检查，禁止 `new Function`、项目内容驱动的 `eval`、`vm` 和动态脚本加载。
- 生产 CSP 测试必须证明不存在 `unsafe-eval`，且恶意项目不能通过脚本标签或 URL 加载代码。
- 条件 AST 和动作命令需要 schema 单元测试、未知操作符测试、深度/步数上限测试和确定性执行测试。
- 恶意字符串、原型污染键、超深 AST、循环引用替代物和超大 payload 必须被边界校验拒绝并返回稳定错误码。
- legacy 插件导入测试必须证明源码未进入 `ProjectDocument`、未执行、未编译、未预览，并能定位隔离原件。
- Web 与 PC 对同一合法 AST fixture 必须产生相同结果，对同一非法 fixture 必须产生等价错误。
- 任何“插件可运行”或“脚本兼容”的 MVP 验收声明均视为违反本 ADR。
